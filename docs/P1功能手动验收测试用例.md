## 0. 前置准备（每区开始前先确认）

1. 系统已通过 `docker compose up -d` 启动（`api-dev` / `web-dev`），用浏览器（桌面 Chrome）访问前端。
2. 角色准备：
   - **平台管理员**账号（能看「知识库与skills / 全库搜索 / 智能体管理 / 产品图库 / 任务中心」等）；
   - **普通用户**账号（只能看「知识库 / 创建新对话」，用于权限与角色门禁用例）；
   - **超级管理员**账号（能看「数据总览 / 知识缺口」，用于运营用例）。
3. 数据准备：
   - 1 个可上传/可索引的测试知识库（已有交付库可直接使用）；
   - 测试文件若干：普通 PDF、**含表格/图片的 PDF**、Word（`.docx`）、Excel（`.xlsx`）、一张**图片**（如资质证书截图）；
   - 做版本用例需先准备同基础名的两个文件（例：`产品手册 v1.0.pdf` 与 `产品手册 v1.1.pdf`）。
4. 每条用例的「通过」以预期结果逐句满足为准；内容类预期（回答正确性、识别准确性）以人工判断为据。

# 一、知识库管理与版本治理（KB）

> 入口：管理员侧栏「知识库与skills」/ 普通用户「知识库」→ 知识库列表；点卡片进详情 `/extensions/knowledgebase/:kbId`。
> 角色提示：涉及 上传/解析/入库/清洗/版本/QA/冲突 的文件行操作仅对**平台管理员**显示（当前实现如此，见 KB-34 权限说明）。

## 1.1 知识库 CRUD 与库设置

- [ ] **KB-01 新建知识库（管理员）**
  - 步骤：知识库列表页点「新建知识库」；选「类型」，选「分类」，填「名称」，选「向量模型」与「分块策略」预设；填「描述」；展开「共享设置」选“指定人/部门/全体”（本轮可不改，保持默认）；点「创建知识库」。
  - 预期：必填未填时被拦并提示；创建成功后新库卡片出现在列表；卡片名与填写的名称一致。

- [ ] **KB-02 列表分类筛选 + 搜索**
  - 步骤：在知识库列表顶部的分类下拉与搜索框操作；把某库的「分类」通过编辑改成一个新值后再按该分类筛选。
  - 预期：筛选只显示对应分类的库；搜索按名称模糊命中；空结果显示「暂无知识库」对应空态。

- [ ] **KB-03 编辑知识库（库级模型与分块）**
  - 步骤：库卡片「编辑」（或详情页顶部「编辑」）→ 改「名称/分类/描述」；在「嵌入模型」下拉切换一个不同模型（观察警告）；勾/取消「自动生成问题」（提示“上传文件后自动生成测试问题”）；改「分块策略」；确认保存。
  - 预期：保存成功；详情页标题与副标题同步更新；切嵌入模型有二次确认/警告文案；自动生成问题开关与分块策略保存后生效（新建上传时体现）。

- [ ] **KB-04 复制知识库 ID**
  - 步骤：卡片菜单或详情页顶部点「复制 ID」。
  - 预期：剪贴板得到该库的 `kb_id`（形如 `kb_xxx`），并有成功提示。

- [ ] **KB-05 删除知识库（用临时库验证）**
  - 步骤：新建一个临时空库 → 卡片菜单「删除」→ 观察确认文案 → 确认。
  - 预期：确认文案含「确定删除知识库「{name}」吗？此操作不可恢复。」；确认后卡片消失；回到列表。后续用例请勿用正式库删除验证。

- [ ] **KB-06 共享设置对访问范围生效**
  - 步骤：建库或编辑库时把「共享设置」从“仅自己”改为“指定人”（选一个普通用户）。用该普通用户登录。
  - 预期：普通用户能看到该库并可点进详情；再把它改回“仅自己可访问”，普通用户刷新后列表中不再出现该库（若此时该用户已无任何可见库，空态显示「管理员授权后可查看维护」）。

- [ ] **KB-07 检索参数配置（库级）**
  - 步骤：详情页「检索测试」tab 右侧管理员可见的「检索配置」面板（SearchConfigPanel）→ 调整参数 → 保存；刷新页面后再打开。
  - 预期：保存有成功提示（「配置已保存」类）；刷新后该库参数被读取（本地按 `search-config-{kbId}` 记忆），不同知识库参数互不串扰。

## 1.2 文件上传与文档处理

- [ ] **KB-08 多模式上传与进度/失败明细**
  - 步骤：文件面板点「上传」→ 弹窗内切换模式：上传文件 / 上传文件夹 / 解析 URL / 工作区；拖入多个文件；观察「上传进度」卡（总计/上传中/排队/失败），点完成项「查看」预览；最后点「添加到知识库」。
  - 预期：四模式入口可见；进度数字实时变化；单文件失败在明细中以红色 errorText 显示原因且不阻断其余文件；队列完成后出现「上传队列已完成，可点击“添加到知识库”继续下一步。」提示；提交后文件出现在列表。

- [ ] **KB-09 同名/重复文件冲突（非版本方式）**
  - 步骤A（内容完全一致）：上传一个与库内某文件**内容完全一致**的文件 → 观察弹窗。
  - 预期A：出现「重复文件」提示（“该文档已存在于「{location}」，为避免重复索引，不能再次入库。”），只能「知道了，跳过」，不会产生第二份。
  - 步骤B（同名但内容不同）：同一目录上传与已存在文件**同名但内容不同**的文件，选择“保留两份 / 作为独立文档”。
  - 预期B：不会静默覆盖原文件；系统会给出显式选择——管理员可能看到「同名文件冲突」弹窗（提供「保留两份 / 替换现有文件」）或「请选择上传文件的处理方式」（选「作为独立文档」）；按所选项生效，选保留则两份都出现在列表（如出现的是另一个弹窗，记录实际文案与结果即可）。

- [ ] **KB-10 增量更新：上传为“新版本”（版本候选生成）**
  - 步骤：上传一个与现有文档**同名**或**同基础名不同版本号**（如现有 `产品手册 v1.0.pdf`，再传 `产品手册 v1.1.pdf`）的文件；系统检测到后出现「请选择上传文件的处理方式」→ 选「作为新版本」并选择目标文档 → 提交。
  - 预期：每文件可单选「作为独立文档 / 作为新版本」；选新版本需选目标文档（或点「搜索文档」跨目录找）；提示「作为新版本时，旧版将保留在版本历史中」；提交 toast：「{count} 个文档版本更新任务已提交，请在任务中心查看处理进度」。任务中心出现「文档解析 / 文档入库」类任务（版本候选的解析/变更分析由后台任务承载）。
  - 提示：同一批次为同一文档提交多个新版本会被拦截（“同一批次不能为同一文档提交多个新版本”）。

- [ ] **KB-11 新版本处理链路（到候选/当前版本）**
  - 步骤：接 KB-10 提交后，在任务中心等到任务完成；回文件列表刷新，观察该文件行状态从「解析中」→（变更分析）→ 某候选状态（如「待审核冲突 / 待审核知识变更 / 新版已拒绝」等静态标签）。
  - 预期：状态随时间流转到终态；无内容变化的版本出现「没有结构化知识变化」；有知识变更则出现「查看变更报告」入口（KB-25/26 继续）。

- [ ] **KB-12 OCR 引擎选择与图片强制**
  - 步骤：上传弹窗展开「OCR 引擎（仅应用于 PDF/图片文件）」popover；观察引擎列表（不启用 / RapidOCR / MinerU / PP-Structure-V3 / DeepSeek OCR / PaddleOCR-VL-1.6 / PP-OCRv6）与健康状态；上传一张图片但不启 OCR 直接提交。
  - 预期：不可用引擎折叠在不可用分组并带说明，可点“检查服务状态”刷新健康；图片未启 OCR 提交被拦：「检测到图片文件，必须启用 OCR 才能提取文本内容。」；PDF/图片文件上传时出现建议 alert（“建议启用 OCR 以提取文本内容”）。

- [ ] **KB-13 自动入库与入库参数配置**
  - 步骤：上传时勾选「上传后自动入库」→ 展开「入库参数配置」→「分块策略」预设 + 「高级」展开（最大 Token 数默认 512 / 重叠比例 / QA split 分隔符）。
  - 预期：勾选后出现参数面板且可保存应用到该批；入库任务提交后在任务中心有“文档入库”任务。

- [ ] **KB-14 上传前 AI 清洗排版**
  - 步骤：上传时勾选「AI 清洗排版」；在清洗面板对某文件「全部清洗」或逐文件清洗；观察“AI 正在清洗排版...”状态；编辑清洗结果；点「添加到知识库」入库。
  - 预期：清洗面板可编辑/预览切换；清洗后入库的文档内容为清洗后的规范文本（可在 KB-20 文件详情 markdown 视图核对）。

- [ ] **KB-15 已入库文档「清洗预览」（草稿-编辑-确认并入库）**
  - 步骤：文件行操作「清洗预览」→ `文档清洗预览` 弹窗；观察左「解析原文」右「清洗结果」对比、「清洗变更与警告」；点「重新生成」；对正文做编辑后点「保存草稿」（提示“保存草稿不会影响当前在线索引”）；再点「确认并入库」（二次确认“系统会切片并写入向量库；已入库文档会在新索引验证成功后切换版本。”）。
  - 预期：清洗中/草稿状态下按钮状态正确；确认后任务提交，最终文件当前版本切换到新清洗内容，且原版本进历史。

- [ ] **KB-16 Office（Word/Excel）上传即编辑**
  - 步骤：上传一个 `.docx` 与一个 `.xlsx`；在弹窗的“Word / Excel 编辑”面板点「编辑」→ Office 编辑器；修改文字/单元格 →「确认并入库」。
  - 预期：可在编辑器内改动并“以原格式入库”；入库后文件详情可看到修改后内容。

- [ ] **KB-17 文件夹：新建子文件夹 / 移动到**
  - 步骤：在文件面板（或文件行“移动到”入口）新建文件夹；建子文件夹；把某文件「移动到」该目录；面包屑导航返回根目录；对虚拟目录尝试重命名。
  - 预期：文件夹可逐级展开/面包屑返回；文件可移动到目标目录且位置更新；虚拟目录只有重命名，没有新建子文件夹等。

- [ ] **KB-18 状态流转与失败重试**
  - 步骤：上传一个可解析文件，观察列表状态列变化：待审核 → 解析中 → 待入库 → （入库中）→ 已入库；另传一个必然解析失败的文件（或临时用不支持格式）。
  - 预期：状态文案与时间戳随阶段更新；解析失败显示红色 pill「重试解析」、入库失败显示「重试入库」等可点击动作；点重试后进入对应处理阶段。（阶段文案：待审核/解析中/待入库/入库中/已入库/入库失败/重试解析/重试入库 等。）

- [ ] **KB-19 批量选择与批量操作**
  - 步骤：点文件列表顶部“多选”进入批量模式；勾选多个“待解析”文件 →「批量解析」；多个“待入库”文件 →「批量入库」；另对无处理项的点批量操作。
  - 预期：批量条出现且数字正确；无待处理文件时提示「没有可解析的文件 / 没有可入库的文件」；批量删除有确认。

- [ ] **KB-20 文件详情弹窗（三视图）**
  - 步骤：点文件行文件名；在详情弹窗切换 原文 / markdown / 分块 三个视图；右上「下载原文 / 下载 Markdown」。
  - 预期：已解析文件默认展示 markdown 内容；分块视图按块号列出（`#n`）；未解析文件自动回退原文视图而非显示“暂无文件内容”；下载动作得到对应文件。

## 1.3 多版本治理

- [ ] **KB-21 版本历史入口与空态**
  - 步骤：对一个从未有过版本的已入库文件行点「操作 → 版本历史」；再对文件夹/虚拟目录行观察操作菜单。
  - 预期：文件夹无“版本历史”入口；文件打开 `版本历史` 弹窗，无记录时显示「暂无版本记录」空态；非平台管理员看不到该入口。

- [ ] **KB-22 版本列表与当前版本标记**
  - 步骤：接 KB-10/11 产生至少两个版本后打开「版本历史」。
  - 预期：每个版本项标题为 `V{版本号} · 文件名`，当前版本带「当前版本」tag，其余带「历史/候选版本」tag（说明：候选与历史暂共用该 tag）；有变更报告的版本显示「查看变更报告」及 新增/变更/删除/冲突 计数；处理失败版本显示 error 信息。

- [ ] **KB-23 版本对比（选基准 → 再点另一版本 → diff）**
  - 步骤：在版本列表对某一版本点「对比」；出现提示「已选 {name} 作为基准（旧版），请再点击要对比的另一个版本…」；再点另一个版本 → 进入对比模式。
  - 预期：顶部为 旧版（base）→ 新版（target）两个下拉，可切换；点「交换 A/B」后两侧互换；差异区有「新增/删除/未变 {n} 行」统计与逐行高亮（新增行/删除行标记）；点「返回版本列表」回到列表。

- [ ] **KB-24 对比：内容一致版本**
  - 步骤：对两个文本完全一致的版本执行对比。
  - 预期：提示「两个版本文本内容一致，无差异」，无差异行渲染。

- [ ] **KB-25 变更报告明细**
  - 步骤：在版本历史点某候选版本的「查看变更报告」。
  - 预期：汇总 tag（新增/变更/删除/冲突 + 数量）；明细逐条列出变更类型、原因、「旧值/新值」与「旧版证据/新版证据」；若自动判定证据不足，显示「知识变更证据不足，需要人工审核」。

- [ ] **KB-26 决策：接受并启用新版 / 拒绝新版**
  - 步骤：对「待审核」的候选版本报告点「接受并启用新版」；另造一个候选点「拒绝新版」（确认文案“拒绝后旧版继续生效，知识变更报告仍会保留。”）。
  - 预期：接受后 toast「新版已生效」；文件当前版本切换为新版，旧版保留在历史；拒绝后当前版本不变且报告仍可查看。

- [ ] **KB-27 历史版本下载**
  - 步骤：版本列表某项点「下载」；来源卡片“历史版本（{count}）”折叠里点单版本「下载」。
  - 预期：下载文件名带版本号（`buildVersionedFilename`），有「历史版本 V{version} 下载成功」提示。

- [ ] **KB-28 文件级冲突审核（需先构造实体冲突数据）**
  - 步骤：让某库存在“实体冲突”数据；文件行操作 →「冲突审核」（KnowledgeConflictModal）。
  - 预期：弹窗展示 KB 级冲突表与多列对比，可选处置方式并保存；若无可测数据则跳过并在旁边注明“无冲突数据，未测”。

## 1.4 检索测试 / QA 对 / 权限

- [ ] **KB-29 检索测试 tab：仅检索 / 预览回答 / 引用来源 / 检索详情**
  - 步骤：详情页「检索测试」tab 输入问题 → 先点「仅检索」（不生成回答，看结果与「检索详情」）；再点「预览回答」。
  - 预期：仅检索时按检索参数返回片段（含 块索引/文件/距离、重排序分、版本标记 `V{version} 当前版本`，可切原始数据）；预览回答出现「回答预览」卡与「模型：{model}」，下方「引用来源」可展开来源卡片。

- [ ] **KB-30 示例问题生成**
  - 步骤：「检索测试」下方「示例问题」区点「生成示例问题」（生成中显示“正在生成示例问题...”）。
  - 预期：toast「成功生成 {count} 个测试问题」，示例问题列表出现并可点选回填。

- [ ] **KB-31 检索测试 tab 的权限可见性**
  - 步骤：用“只有只读权限（无 can_search）”的普通用户进入该库详情。
  - 预期：不可见「检索测试」tab；顶部不出现检索配置。有 can_search 的用户可见该 tab。

- [ ] **KB-32 库内 QA 知识对（per-file）**
  - 步骤：文件行「QA 知识对」→ 弹窗「自动生成草稿」或「手工新增」；填写 问题/答案/来源块/证据（提示“证据必须逐字摘录”）；「保存草稿」→ 对草稿「确认并同步」；对某草稿「拒绝」（确认“拒绝后，自动生成不会静默恢复相同问题”）；观察来源 tag（人工/自动）与状态 tag。
  - 预期：可生成/手工新增/批量确认；已同步对状态为已确认；正文变化的对出现「正文已变化，需复核」tag；空库显示「暂无 QA 知识对」。

- [ ] **KB-33 权限面板：授权类型/预设/权限位**
  - 步骤：详情页顶部或底部「权限设置」→ 新建授权：选「授权类型」（用户/部门/团队/角色）→ 选「授权对象」→ 选预设（只读/编辑者/管理者）并勾选权限位（查看/问答/上传/下载/删除/管理/授权/导出）→「保存授权」。
  - 预期：列表汇总 创建者/共享设置/授权 三类来源；保存有成功提示；行删除有确认「确认删除这条授权？」；页面有说明「平台管理员与超级管理员默认拥有该知识库的全部权限（无需单独授权）」。

- [ ] **KB-34 权限生效：只读 vs 平台管理员（含半套说明）**
  - 步骤：给某普通用户授一个预设（如“只读”，含 查看+问答），用该用户进库并逐项试 检索测试/上传/行操作/权限 tab；再用平台管理员对比同一库。
  - 预期：只读用户可 查看文件列表、用「检索测试」问答，但没有可用的上传/文件管理入口；**注意**：按当前实现，文件行级管理操作（解析/入库/版本/清洗/QA/冲突）的可见性绑定**平台管理员**——即便把“管理者”预设授予普通用户，该用户在文件行内仍看不到这些按钮（详情页顶部“编辑”与检索配置等受 can_manage 影响）。请按此验收，并标注是否符合预期权限设计。

# 二、对话问答（CHAT）

> 入口：左侧「创建新对话」进入 `/agent`。下方每条均以该 agent 实际配置的知识库为前提；来源面板展开点「来源」按钮。

## 2.1 基础对话 / 追问 / 历史

- [ ] **CHAT-01 新对话 + 多轮追问**
  - 步骤：新对话 → 问一个知识库相关问题 → 就同一话题追问第二、三轮（含代词/指代，如“它/那里面”）。
  - 预期：多轮上下文生效，回答能理解指代；每轮回答带引用来源；侧栏生成该会话条目，标题取自首问。

- [ ] **CHAT-02 会话历史 / 继续对话**
  - 步骤：刷新页面 → 左侧会话列表点击此前会话；发送一条新问题。
  - 预期：历史消息完整恢复；新问题在该线程内继续回答，并理解上文（“继续对话”成立）。

- [ ] **CHAT-03 英文问答**
  - 步骤：用英文提问一个知识库问题（示例：`What are the operating hours?` 按库内容替换）。
  - 预期：回答为英文；来源引用正常；切换整站语言（见 SYS-01）不影响回答语言由提问决定。

- [ ] **CHAT-04 引用来源面板与文档片段详情**
  - 步骤：一条有知识库检索的回答点「来源」按钮展开；点某来源卡片的文档片段；再收起。
  - 预期：面板列出命中文档与片段、相关度/重排序分数；点片段弹出「文档片段详情」（含行号范围与版本标记）；再次点击「来源」收起。

- [ ] **CHAT-05 来源卡片的版本徽标与历史版本下载**
  - 步骤：对一个有多版本的文档命中来源，观察卡片头；展开「历史版本（{count}）」；下载单个历史版本；点「查看文件」「下载原文」。
  - 预期：当前命中版本带 `V{version} 当前版本` 徽标；历史版本可逐一下载（文件名带版本）；「查看文件」打开文件详情弹窗。

- [ ] **CHAT-06 答案操作条（复制）**
  - 步骤：在助手回答的 refs 条点复制图标。
  - 预期：复制成功提示（“文本已复制到剪贴板”），图标短暂变为对勾。

- [ ] **CHAT-07 上下文使用 / 模型信息**
  - 步骤：在对话中打开右侧/底部上下文面板或悬停模型名（bot 图标 + 模型名）。
  - 预期：显示当前模型名与上下文使用（当前上下文 / Token 构成等）；回答生成中的状态文案随阶段变化（正在思考/正在调用工具…）。

## 2.2 结构化输出

- [ ] **CHAT-08 输出格式选择（默认/表格/步骤/列表）**
  - 步骤：发送栏附近的格式控件依次切到 格式·表格 / 格式·步骤 / 格式·列表 / 格式·默认，各发一个适合该结构的问题（如“列出三个型号及参数”）。
  - 预期：回答分别以表格/步骤/列表/普通段落呈现；不强行结构化的提问也给出合理排版。

- [ ] **CHAT-09 格式选择按会话记忆**
  - 步骤：在 格式·表格 下发问并收到表格；不重置的情况下发下一个相关问题（不重新选择）。
  - 预期：下一个回答仍按表格格式（该线程记住格式偏好）；刷新页面后格式回到默认（不做跨刷新持久化，属已知半套）。

## 2.3 图片检索 / 输出（资质联动）

- [ ] **CHAT-10 对话内上传图片附件（OCR 引擎）**
  - 步骤：在输入区点附件/图片上传一张图片（如证书、表格截图）；需要时选择 OCR 引擎（可观察健康状态）；发送。
  - 预期：图片作为消息附件发出（气泡内可见）；解析型提问可基于图片内容回答（如“图里证书编号是多少”），回答时可能带 OCR/文件工具调用状态。

- [ ] **CHAT-11 图片内容识别准确性（资质类）**
  - 步骤：上传一张资质/证书图片并提问其中关键字段（证书编号/有效期/发证机构）。
  - 预期：识别结果与图面一致（人工核对），回答可附引用来源或说明解析来源；若识别错误则标为不通过。

- [ ] **CHAT-12 回答中图片预览放大**
  - 步骤：当回答/消息包含图片时点击该图片。
  - 预期：弹出图片预览 lightbox（可放大查看、关闭），不跳转页面。

## 2.4 主动追问（澄清 interrupt）与中断

- [ ] **CHAT-13 Agent 主动澄清提问**
  - 步骤：故意给一个**信息不足**的问题（提问存在歧义/缺参数，触发 `ask_user_question`）；观察消息条出现提问卡片（单选/多选/“其他：请输入自定义内容”输入框），如有多个子问题则按 tab 逐项回答 → 提交。
  - 预期：Agent 暂停生成并主动提问澄清；提交所选/自定义内容后继续生成，答案基于澄清结果；提问中可点“下一项”处理多项。

- [ ] **CHAT-14 停止生成 / 中断后可继续**
  - 步骤：发一个长问题，在生成中点“停止/打断”。
  - 预期：生成中止并提示（“你停止生成了本次回答”）；随后可继续追问或重发，不残留死循环。

## 2.5 答案评价

- [ ] **CHAT-15 点赞 👍**
  - 步骤：在某条回答点 👍。
  - 预期：提示“感谢您的反馈！”；再次点按提示“您已经提交过反馈了”，图标置灰不可重复提交。

- [ ] **CHAT-16 点踩 👎（必选原因 + 补充说明）**
  - 步骤：在某条回答点 👎 → 弹窗「请告诉我们不满意的原因」；不选原因直接提交（应被拦：“请选择一个不满意的原因”）；选「答案有误」并填补充说明 → 提交。
  - 预期：原因必选；可选补充说明（≤500 字）；提交成功提示并置灰；返回数据总览-反馈统计可看到该条点踩及原因（见 OPS-12）。

## 2.6 问答侧多版本提示 / 澄清

- [ ] **CHAT-17 基于当前版本的提示注记**
  - 步骤：让知识库中存在“该文档当前版本 V1、另有历史 V0”（可先按 KB-10 造一个多版本文档再提问，使其命中）。
  - 预期：回答底部（refs 区顶部）出现注记：「本回答基于《{文档名}》当前版本 V1 生成，历史版本未参与本次回答。」仅在存在真实历史版本时出现。

- [ ] **CHAT-18 版本意图澄清**
  - 步骤：对同一多版本文档提问带有版本意图（如“V1 相比 V0 改了哪几条”“上一版怎么写的”）。
  - 预期：命中版本意图时出现澄清注记（“您的问题可能涉及文档版本。”），说明当前版本号与历史版本、并引导“如需查看某版内容或版本差异，请使用文件侧『版本对比』或历史版本预览。”；可在文件侧完成对比闭环。

## 2.7 智能转人工（拒答转人工）

- [ ] **CHAT-19 转人工按钮出现条件**
  - 步骤：在「业务域」配置了一个 domain 的 agent 下，问一个该域内且知识库确实无法回答的问题（触发拒答）；观察回答底部。
  - 预期：拒答且命中业务域时回答消息区出现「转人工」按钮（红色描边样式）；纯聊天无拒答不出现。
  - 前置：先完成 SYS-13 企微客服配置与 SYS-14 业务域字段。

- [ ] **CHAT-20 未配置企微时的兜底**
  - 步骤：临时把某 agent 业务域对应的企微客服 URL 留空（或全局也留空），触发一次该域拒答并点「转人工」。
  - 预期：不会打开无效客服；给出“企业微信客服入口尚未配置”类提示，不崩溃。（测试后恢复配置。）

- [ ] **CHAT-21 按业务域路由转人工**
  - 步骤：配置：全局 URL 为空、按业务域 `{domainA}` → URL-A、`{domainB}` → URL-B；在 domainA 的 agent 拒答点「转人工」。
  - 预期：打开 URL-A（域级命中）；domainB 触发时打开 URL-B；未配域/全局空的域点击给出“企业微信客服入口尚未配置”。
  - 再配全局 URL-G 后：未配域的 domainC 拒答转人工应回退打开 URL-G。

- [ ] **CHAT-22 转人工记录与状态**
  - 步骤：完成一次转人工点击后观察按钮状态与提示；在拒答分类/域有记录的前提下可在运营数据（见 OPS）核对。
  - 预期：点击过程有“正在打开企业微信客服”状态；成功后在新标签打开客服入口；按钮状态不再可重复误触（或给出已发起提示）。

# 三、运营闭环（OPS）

> 入口：超级管理员侧栏「数据总览」（`/dashboard`）与「知识缺口」（`/knowledge-gaps`）。

## 3.1 知识缺口处理闭环

- [ ] **OPS-01 缺口列表与筛选**
  - 步骤：先制造 1~2 条缺口（用配置库的 agent 问无答案/知识库未覆盖问题产生拒答，等缺口入库）；打开「知识缺口」页；分别按 状态（全部/新发现/处理中/已解决/已忽略）与 原因（无可用知识库/没有检索结果/检索正文为空/候选证据不足）筛选。
  - 预期：列表显示问题、拒答原因、次数、操作列“补答”；筛选与搜索生效；空态正常。

- [ ] **OPS-02 缺口详情抽屉**
  - 步骤：点某条缺口的详情/行进入详情。
  - 预期：抽屉展示 拒答原因、出现次数、知识库范围、最近用户、最近会话、首次出现/最近出现、处理备注、未覆盖问题原文、Agent 信息。

- [ ] **OPS-03 人工补答（手工 / 联网草稿）**
  - 步骤：缺口操作列「补答」→「人工补答」弹窗：直接输入答案，或点「联网搜索生成草稿」（生成中提示“正在联网检索并生成候选答案...”）→ 得到候选答案与「参考来源」→ 在答案框编辑。
  - 预期：可直接输入；联网草稿生成后带来源列表；来源为空时显示“暂无可展示来源”；联网未生成草稿时给“请结合来源人工填写”提示。

- [ ] **OPS-04 确认并保存问答对**
  - 步骤：补答框填好答案 → 「确认并保存问答对」（说明：“保存的答案会作为人工问答对，同一智能体再次收到相同问题时才优先使用，不会自动进入普通问答。”）。
  - 预期：toast「已保存人工问答对，知识缺口已标记为已解决」；该条缺口状态变「已解决」。

- [ ] **OPS-05 闭环验证：再问命中人工答案**
  - 步骤：换到配置库 agent 的对话页，再次提交与该缺口**相同**的问题。

- [ ] **SYS-02 登录页语言与刷新保持**

## 4.2 三层角色 / 用户 / 部门 / 团队管理

- [ ] **SYS-04 用户列表与新增用户**
  - 步骤：设置 →「用户管理」tab → 搜索/按角色与部门筛选 →「添加用户」：填 用户名（自动生成 UID，可改，提示“登录ID：{uid}”）、手机号（可选）、角色、部门/团队（未选团队则进默认团队）、初始密码。
  - 预期：列表支持 搜索用户名/ID/手机号 与 全部部门/全部权限 筛选；新建后新用户可用 UID 登录。

- [ ] **SYS-05 编辑用户 / 修改密码**
  - 步骤：行内「编辑用户」改角色/部门/团队/手机号；「修改密码」流程。
  - 预期：编辑保存成功；角色选项与“超级管理员账户无法修改角色”提示逻辑一致（对 superadmin 不可改）；新密码生效。

- [ ] **SYS-06 批量导入用户**
  - 步骤：「导入用户」→ 下载 Excel 模板 → 按要求填写 3~5 行（含 1 行错误如重复 UID/手机号格式错）→ 选择 Excel → 校验。
  - 预期：校验通过提示“共 {n} 个用户，确认后将一次性导入”；有错误时提示“共 {r} 行，发现 {p} 个问题，未导入任何用户”并列出 Excel 行/字段/问题；有明文初始密码安全提示（“导入后请立即安全删除或妥善保管文件”）；确认后成功导入对应数量。

- [ ] **SYS-07 删除用户**
  - 步骤：行内「删除用户」；尝试删除自己的账号。
  - 预期：确认文案“此操作不可撤销”；删除后该用户无法登录；自己不能被删除（“不能删除自己的账户”）。删除后不可恢复。

- [ ] **SYS-08 部门管理（添加部门必建管理员）**
  - 步骤：设置 →「部门管理」→「添加部门」：填部门名称 + 管理员 UID/密码（手机号可选）；观察“此 UID 将用于登录”；保存。
  - 预期：必须提供管理员 UID（3-20 位字母数字下划线）与密码；UID 冲突/格式错误有前置校验；创建成功提示含新管理员（“管理员 {uid} 已创建”）；新管理员可登录并按部门隔离用户。
  - 再测「编辑部门」「删除部门」（删除确认含“用户迁移到默认部门、部门配置与部门 API Key 一并清理”）。

- [ ] **SYS-09 团队管理**

  - 预期：勾选用户进入该团队；取消勾选的原成员回到本部门默认团队（提示文案正确）；默认团队为用户未分配时的兜底桶。

- [ ] **SYS-10 角色门禁（导航可见性 + URL 直访）**
  - 步骤：分别用 user / admin / superadmin 登录对比侧栏菜单；再用 admin 浏览器地址栏直接访问 `/dashboard`、`/knowledge-gaps`；用 user 直接访问 `/model-manage`、`/knowledge-browser`、`/product-images`。
  - 预期：导航按角色显示（user 看不到 全库搜索/智能体管理/产品图库/数据总览/知识缺口；admin 看不到 数据总览/知识缺口）；URL 直访超管页被守卫拦截。
  - 说明：`/model-manage` 与 `/knowledge-browser` 路由当前**无 admin 守卫**——URL 直访能否打开请如实记录；这是「半套」项，交由产品确认是否需收紧。

- [ ] **SYS-11 库级授权后的普通用户视角（与 KB-33/34 联动）**
  - 步骤：用被授了具体权限（如 查看+问答）的普通用户登录，进入被授权库。
  - 预期：可按权限 查看/检索问答；无权限操作（上传/删除等）入口不可见或被拦；未授权库不可见（如 KB-06 共享设置配合）。结合 KB-34 的半套说明一起验收。
