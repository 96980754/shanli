## 2. 知识库管理（5 条 P1）

入口：管理员侧栏「知识库与skills」/ 普通用户「知识库」→ 知识库列表；点卡片进详情 /extensions/knowledgebase/:kbId。
角色提示：涉及上传/解析/入库/清洗/版本/QA/冲突 的文件行操作仅对平台管理员显示（当前实现如此，见 KB-34 权限说明）。

### 2.1 KB-P1-1 文档处理能力：复杂表格（含图片）/ 图片 解析　🟡

现状：上传弹窗内置 6 种 OCR/结构引擎（RapidOCR / MinerU / PP-Structure-V3 / DeepSeek OCR / PaddleOCR-VL-1.6 / PP-OCRv6）且带健康状态；图片强制 OCR；解析后以 markdown/分块呈现可人工核对。判定口径：入口与能力 ✅，解析效果（复杂表格版式、表格内图片、图片文字）以所选引擎为准，人工验收。

- [ ] KB-12 OCR 引擎选择与图片强制
- 步骤：上传弹窗展开「OCR 引擎（仅应用于 PDF/图片文件）」popover；观察引擎列表（不启用 / RapidOCR / MinerU / PP-Structure-V3 / DeepSeek OCR / PaddleOCR-VL-1.6 / PP-OCRv6）与健康状态；上传一张图片但不启 OCR 直接提交；再上传一张含表格与图片的 PDF（勾选较适合复杂版式的引擎，如 PP-Structure-V3 / MinerU）。
- 预期：不可用引擎折叠在不可用分组并带说明，可点“检查服务状态”刷新健康；图片未启 OCR 提交被拦：「检测到图片文件，必须启用 OCR 才能提取文本内容。」；PDF/图片文件上传时出现建议 alert（“建议启用 OCR 以提取文本内容”）。
- [ ] KB-20 文件详情三视图（用复杂表格/图片 PDF 核验解析结果）
- 步骤：对上述入库的复杂表格/图片文件点行内文件名；在详情弹窗切换 原文 / markdown / 分块 三个视图；右上「下载原文 / 下载 Markdown」。
- 预期：已解析文件默认展示 markdown 内容，表格以 markdown 表格呈现、图片区域有对应占位/附件，分块视图按块号列出（#n）；表格单元格文字与图内文字能检索到（可回 KB-29 检索验证）；下载动作得到对应文件。
- 判定：复杂表格列/单元格内容、图内关键文字能被 OCR/结构引擎正确还原即通过；还原缺失属引擎能力边界，记录引擎与现象即可，不机械判败。

### 2.2 KB-P1-2 知识更新：增量更新（仅处理变更文档并更新索引）　🟡

现状（半套）：增量链路已实现——上传同名/同基础名文件时系统检测冲突，走「上传 + 作为新版本」后，仅该变更文档被重新解析/索引（含内容哈希判重：内容一致的同名文件被拦，不重复入库；内容变更则生成版本候选进入变更分析/入库任务）。差异：需求表述的“检测机制 + 批量仅处理变更文档”目前没有独立批量增量检测入口，逐文档增量以上传触发。

- [ ] KB-09 同名/重复文件冲突（内容一致的判重拦截）
- 步骤A：上传一个与库内某文件内容完全一致的文件 → 观察弹窗。
- 预期A：出现「重复文件」提示（“该文档已存在于「{location}」，为避免重复索引，不能再次入库。”），只能「知道了，跳过」，不会产生第二份——未变更文档不会被重复处理/索引。
- 步骤B：同一目录上传与已存在文件同名但内容不同的文件，选择“保留两份 / 作为独立文档”。
- 预期B：不会静默覆盖原文件；出现显式选择（“同名文件冲突”：保留两份/替换现有文件，或“处理方式”：作为独立文档），按选择生效。
- [ ] KB-10 增量更新：上传为“新版本”（仅处理变更文档）
- 步骤：上传与现有文档同名或同基础名不同版本号（现有 产品手册 v1.0.pdf，再传 产品手册 v1.1.pdf）的文件；出现「请选择上传文件的处理方式」→ 选「作为新版本」并选择目标文档 → 提交。
- 预期：每文件可单选「作为独立文档 / 作为新版本」；选新版本需选目标文档（可「搜索文档」跨目录）；提示“作为新版本时，旧版将保留在版本历史中”；提交 toast：「{count} 个文档版本更新任务已提交，请在任务中心查看处理进度」。任务中心出现「文档解析 / 文档入库」任务（版本候选的解析/变更分析由后台任务承载）。同一批次为同一文档提交多个新版本会被拦截。
- [ ] KB-11 增量处理后链路（到候选/当前版本）
- 步骤：接 KB-10 提交后，任务中心等到任务完成；回文件列表刷新，观察该文件行状态从「解析中」→（变更分析）→ 某候选状态（「待审核冲突 / 待审核知识变更 / 新版已拒绝」等静态标签）。
- 预期：状态随时间流转到终态；无内容变化的版本出现「没有结构化知识变化」（不会被索引为重复知识）；有知识变更则出现「查看变更报告」入口（KB-25/26 决策）。

### 2.3 KB-P1-3 预览与调试：导入/更新后可提问预览并调试　✅

现状：库详情「检索测试」tab = 管理员侧调试验证台（仅检索 / 预览回答 / 引用来源 / 检索详情 / 版本徽标），回答底稿可见“模型：{model}”便于比对不同模型参数下的效果。入口：详情页 →「检索测试」。

- [ ] KB-29 检索测试 tab：仅检索 / 预览回答 / 引用来源 / 检索详情
- 步骤：详情页「检索测试」tab 输入问题 → 先点「仅检索」（不生成回答，看结果与「检索详情」）；再点「预览回答」。
- 预期：仅检索时按检索参数返回片段（含 块索引/文件/距离、重排序分、版本标记 V{version} 当前版本，可切原始数据）；预览回答出现「回答预览」卡与「模型：{model}」，下方「引用来源」可展开来源卡片——用于导入/更新后核对新内容是否被检索到、回答是否符合预期。
- [ ] KB-30 示例问题生成（调试辅助）
- 步骤：「检索测试」下方「示例问题」区点「生成示例问题」（生成中显示“正在生成示例问题...”）。

### 2.4 KB-P1-4 问答调优：编辑答案更新问答对（下次直接命中）　✅

### 2.5 KB-P1-5 问答调优：AI 答不上 → 管理员联网咨询 AI → 确认 → 保存问答对　✅

现状：知识缺口闭环已交付——AI 拒答问题进入「知识缺口」，管理员可「联网搜索生成草稿」后人工确认答案，确认后保存为人工问答对并标记缺口已解决；再问直接命中。

- [ ] OPS-01 制造缺口并列表筛选
- 步骤：用配置库的 agent 问无答案/知识库未覆盖问题产生拒答，等缺口入库；打开「知识缺口」页；按 状态（全部/新发现/处理中/已解决/已忽略）与 原因（无可用知识库/没有检索结果/检索正文为空/候选证据不足）筛选。
- 预期：列表显示问题、拒答原因、次数、操作列“补答”；筛选与搜索生效。
- [ ] OPS-02 缺口详情抽屉
- 步骤：点某条缺口的详情/行进入详情。
- 预期：抽屉展示 拒答原因、出现次数、知识库范围、最近用户、最近会话、首次/最近出现、未覆盖问题原文、Agent 信息、处理备注。
- [ ] OPS-03 人工补答（手工 / 联网草稿）
- 步骤：缺口操作列「补答」→「人工补答」弹窗：直接输入答案，或点「联网搜索生成草稿」（生成中提示“正在联网检索并生成候选答案...”）→ 得到候选答案与「参考来源」→ 在答案框编辑。
- 预期：可直接输入；联网草稿生成后带来源列表；来源为空显示“暂无可展示来源”；联网未生成草稿时提示“请结合来源人工填写”。
- [ ] OPS-04 确认并保存问答对
- 步骤：补答框填好答案 →「确认并保存问答对」（说明：“保存的答案会作为人工问答对，同一智能体再次收到相同问题时才优先使用，不会自动进入普通问答。”）。
- 预期：toast「已保存人工问答对，知识缺口已标记为已解决」；该条缺口状态变「已解决」。
- [ ] OPS-05 闭环验证：再问命中人工答案
- 步骤：换到配置库 agent 的对话页，再次提交与该缺口相同的问题。
- 预期：回答优先直接返回 OPS-03 保存的人工答案（命中 QA 对）；可观察“人工”标识/无检索来源。若未命中请记录为不通过并附实际现象。
- [ ] OPS-06 状态人工流转（处理中/忽略）
- 步骤：对一条缺口执行忽略或将处理备注写回。
- 预期：状态可从新发现流转到处理中/已解决/已忽略，列表筛选同步；备注可保存。

## 3. AI 问答能力（3 条 P1）

入口：左侧「创建新对话」进入 /agent。以下每条以该 agent 实际配置的知识库为前提；来源面板展开点「来源」按钮。

### 3.1 AI-P1-1 多轮对话（上下文记忆）　✅

- [ ] CHAT-01 新对话 + 多轮追问（上下文/指代记忆）
- 步骤：新对话 → 问一个知识库相关问题 → 就同一话题追问第二、三轮（含代词/指代，如“它/那里面”）。

现状与差异：只按当前版本材料作答；回答底部（来源区）给出注记“历史版本未参与本次回答”，并对命中来源的当前版本打 V{n} 当前版本 徽标、「历史版本」折叠可展开逐一下载/对比；提问含版本意图时触发版本澄清注记，引导到文件侧版本对比。与需求表“同时给出历史版本材料回答”存在设计出入——历史版本当前不参与检索、不在正文同时作答。判定：主体（当前版优先）✅；“正文同时给历史版答案”请产品确认是否需要改为版本并联检索。测试前先按 KB-10 造一个多版本文档。
