# 线索-交付全流程

## 参与角色
- 客服
- 销售运营
- 销售/销售总监
- 行销
- 产品管理
- 产品总监
- 交付
- 交付经理
- 财务
- 销售总经理
- 产品总经理
- 董事长
- 产品研发
- 产品运营
- 采购
- 仓库
- 高级供应链

## 流程步骤

### 1. 线索接收与有效性判断
- 客服输出需求。
- 判断线索有效性：
  - 有效线索 → 进入商机。
  - 无效线索 → 不进入后续商机流程。

### 2. 商机与需求评估
- 有效线索进入商机，执行需求评估流程。
- 输出方案、预算[存疑]及标准化产品清单等。
- 决策人：研发、交付、销售、行销、产品经理、产品运营、高级供应链。
- 需求评估输出：
  - 标准化产品。
  - 非标准化产品。

### 3. 报价流程
- 销售提供：项目背景、项目申请价格、价格策略、竞品分析、付款方式、项目风险等。
- 发起报价审批。
- 产品类型分支：
  - 标准化产品且涉及交付 → 交付核算、审批。
  - 非标准化产品 → 产品总监评估；若解决方案变化导致评估不通过，则报价不通过。
- 审批权限：
  - 超权限 → 提交上级审批（如销售总经理权限审批）。
  - 满足“直接引用解决方案清单、报价审批一致；价格政策内，现款现货” → 确认报价。
  - 若引用报价解决方案清单但报价有变 → 重新发起审批/超权限审批。
- 审批结果：
  - 同意 → 进入合同流程。
  - 不同意 → 流程终止/返回调整。

### 4. 合同流程
- 确认合同方案。
- 产品类型分支：
  - 标准化解决方案清单调整，不涉及交付 → 按标准合同确认。
  - 标准化产品且涉及交付 → 交付部门确认。
  - 非标准化产品 → 产品总监评估；不通过条件：解决方案变化，产品总监评估不通过。
- 审批权限：
  - 超权限 → 销售总经理权限审批。
  - 同意 → 合同盖章、合同归档。
  - 不同意 → 流程终止/返回调整。

### 5. 需求澄清会
- 参会人员：销售、销售运营、产品运营、交付经理及项目交付相关人员。
- 非标准化产品：
  - 定制化开发。
  - 输出需求。
  - 开发解决方案。
  - 开发完成入库（账号、终端类，库存）。
- 标准化产品：
  - 输出需求。
  - 进入交付准备。

### 6. 实施方式评估
- 进行需求评估、制定实施计划。
- 评估后确定实施方式：
  - 自行实施。
  - 外包实施。

### 7. 采购与库存管理
- 标准化产品输出需求后：
  - 询价比价、供应商审核/建档。
  - 判断库存是否满足：
    - 库存不满足 → 发起采购（采购引入、入库、确认交期）。
    - 库存满足 → 直接进入发货流程。
- 采购/审批通过 OA 流程发起，库存与交付信息通过云星空同步。

### 8. 发货与交付验收
- 交付部门按发货流程发货。
- 根据不同产品、交付情况生成验收报告/竣工[存疑]报告。
- 完成验收，验收报告归档。

## 关键判断与分支
- 线索是否有效：
  - 有效 → 商机/需求评估。
  - 无效 → 不进入商机。
- 需求评估结果：
  - 通过 → 标准化产品。
  - 不通过 → 非标准化产品。
- 产品是否涉及交付：
  - 涉及交付 → 交付核算/交付确认。
  - 不涉及交付 → 按标准方案/合同处理。
- 报价/合同是否超权限：
  - 超权限 → 上级审批（销售总经理权限等）。
  - 权限内 → 直接审批。
- 报价确认条件：
  - 满足“直接引用解决方案清单、报价审批一致；价格政策内，现款现货” → 确认。
  - 引用报价解决方案清单但报价有变 → 重新审批/超权限审批。
- 非标准化产品评估：
  - 通过 → 继续后续流程。
  - 不通过（解决方案变化，产品总监评估不通过）→ 流程终止/返回。
- 审批结果：
  - 同意 → 进入下一流程。
  - 不同意 → 返回调整/终止。
- 实施方式评估：
  - 自行实施。
  - 外包实施。
- 库存是否满足：
  - 满足 → 发货。
  - 不满足 → 发起采购。
